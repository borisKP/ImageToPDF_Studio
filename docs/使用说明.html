三步出文件

① 添加工具栏「添加图片 / 添加文件夹 / 添加压缩包」，或把图片、文件夹、压缩包直接拖进窗口。列表显示缩略图、序号与像素尺寸。
② 排序右上角选排序依据后点「应用排序」；也可列表内拖拽、右键置顶 / 上移 / 下移 / 置底、仅对选中项排序。
③ 生成设页面尺寸与压缩档位 → 选保存目录与文件名 → 「生成 PDF」。完成后可直接打开输出文件夹。

解压体积上限（v1.7 起不再自动终止）

旧版遇到解压内容超过 1 GB 会直接中止并提示「疑似压缩包炸弹」。现在「⑤ 压缩包解压上限」可自行配置，超限时由你决定是否继续：

设置行为
解压总体积上限默认 1 GB；可设 0（不限制）～100 GB；快捷按钮 1 GB / 3 GB / 10 GB / 不限制
超限时弹窗询问是否继续默认开启：弹窗「继续 / 中止」，点「继续」即完整解压该包。一次导入只询问一次
关闭询问超限时直接中止该压缩包并提示如何调高上限；其它压缩包继续处理，程序不会退出
单文件 100 MB、最多 500 张图片仍为固定安全限制。若经常导入大图包，建议直接设「不限制」或 10 GB。

左侧视图切换（预览小图 ⇄ 纯文字详细信息）

左侧顶部按钮「切换为：详细信息 / 切换为：预览小图」。两种模式共用同一份顺序，切换不丢排序：

模式显示内容
预览小图缩略图 + 序号 + 文件名 + 像素尺寸，可直接拖拽调整顺序
详细信息（文字版）不显示、也不生成任何预览图；9 列表格：# / 文件名 / 格式 / 像素尺寸 / DPI / 页面尺寸(mm) / 文件大小 / 修改时间 / 所在路径

「页面尺寸(mm)」按右侧当前页面设置实时计算，切换 A4 / 固定 DPI / 最长边限制后该列自动重算。文字视图同样支持右键置顶、上移、下移、置底、仅选中项排序、移除，以及双击预览大图；在文字视图中选中行后，工具栏按钮照常生效。

页面尺寸：不强制 A4

默认读取每张图片自身的 DPI 元数据，按 像素 ÷ DPI × 72 = 页面 pt 生成页面。横图横页、竖图竖页，每页尺寸可以不同，与 Acrobat「保留原始尺寸」一致。实测示例：

源图片DPI生成页面
3000 × 2000 横图300720 × 480 pt（10 × 6.67 英寸）
1200 × 1800 竖图150576 × 864 pt（8 × 12 英寸）
1600 × 900 截图961200 × 675 pt（16.7 × 9.4 英寸）
选项作用
读取图片自带 DPI默认。元数据缺失时用「默认 DPI」（96）。
固定 DPI忽略元数据，全部按指定 DPI 换算页面，输出尺寸可预测。
最长边限制限制页面最长边（如 297mm）。手机照片常写 72/96 DPI，不限制会生成几十英寸的巨页。
统一纸张尺寸需要 A4 / A3 / A5 / Letter / 自定义 mm 时用；横图自动切横向纸张，可设页边距，图片等比居中。
页面物理尺寸在压缩前后始终不变；压缩只降低嵌入图像的分辨率，不会把页面缩成 A4。

压缩：仿 Acrobat DC「PDF 优化器」

处理链：计算图像在页面上的实际 ppi → 超过触发阈值则按双立方（LANCZOS）下采样到目标 ppi → baseline JPEG 编码（高质量自动 4:4:4）→ 仅图形类图片尝试调色板 PNG → 与无损流比体积取小者。目标 ppi 下限 72，低于 96 会实时提示。

移动端显示异常：原因与对策（v1.3 已修复）

原因证据 / 表现v1.3 处理
渐进式 JPEG实测暴力压缩档 PDF 内出现 jpeg PROGRESSIVE + /DCTDecode。ISO 32000 明确指出嵌入 PDF 用渐进式 JPEG「没有好处，解码更慢、更耗内存」；PWG PDF/is 直接禁止；Adobe 兼容性附录 H 记载其与 DCTDecode 组合的历史兼容问题。移动端解码器内存小、实现简化 → 花屏 / 半幅 / 白页。强制 progressive=False，只输出 baseline
照片被 256 色量化「取字节最小者」会让调色板 PNG 对照片也胜出，产生色带、色块；PyMuPDF 又会把 P 模式 PNG 展开成 Flate RGB 原始像素流，解码内存峰值更高。按「前 16 高频色覆盖率 ≥ 45%」自动识别截图 / 线稿，只有图形类才允许量化
有效分辨率过低48–72 ppi 的图被拉伸到 254–423 mm 页面，手机上放大 2–3 倍 → 马赛克、文字糊、细线消失。这不是文件损坏，是采样不足。目标 ppi 下限 72；低于 96 实时提示
页面物理尺寸过大96 dpi 手机照会生成 423×238 mm 甚至更大页面，移动端渲染位图易超 GPU 纹理 / 内存上限 → 白页。用「最长边限制 297 mm」
AES-256 加密（若同时开启）V5 / R6 加密。旧移动阅读器不支持时会静默显示空白页而非提示输密码，极易误判成「压缩把文件压坏了」。移动端白页时改用 AES-128 / RC4-128 或不加密
想更小又不异常：先设「最长边限制 297 mm」缩小页面，再保持 120–150 ppi、把 JPEG 质量降到 60–70。体积按页面面积平方下降，画质与兼容性都保住。不要靠继续压低 ppi 或启用渐进式 JPEG 换体积。

实测v1.3 全档位检查：JPEG 均为 BASELINE，照片不再走调色板 PNG，ppi 不低于 72。

打开/翻页卡：为什么「最小」不等于「最适合阅读」

同一张 4000×2250 截图，三种做法实测（PyMuPDF 单页渲染 3 次取平均）：

做法PDF 体积解码后位图单页渲染
PNG / FlateDecode（体积最小）42 KB25.7 MB97.1 ms
baseline JPEG / DCTDecode（全分辨率）284 KB25.7 MB76.1 ms
v1.4 阅读优先 + 移动端优化66 KB3.2 MB20.3 ms

PNG 在 PDF 里是 /FlateDecode，阅读器要先把整幅图解压成原始 RGB 像素再贴图；JPEG 是 /DCTDecode，走专用（常有硬件加速）解码路径。程序内实测 Flate 单位解码成本约为 DCT 的 8 倍 —— 3000×2000 的 JPEG 渲染 14.8 ms，1600×900 的 PNG 却要 29.6 ms。所以文件最小反而最卡。单页 25.7 MB 位图在手机上反复分配/释放，翻页必然顿；页面 1920×1080 pt（677×381 mm）还会让渲染位图超 GPU 纹理上限。

PyMuPDF 2.1 已移除 PDF 线性化（Linearisation is no longer supported），「快速 Web 查看 / Fast Web View」不可用；提速只能靠图像编码 + 页面尺寸 + 像素上限。

v1.4 做法：先转格式，再做 PDF

控件作用
移动端一键优化一键设为 120 ppi / 质量 70 / 最长边 297 mm / 单页 ≤4 MP / 统一 baseline JPEG；若已加密，自动把 AES-256 降为 AES-128
阅读流畅优先生成 PDF 前先把每张图统一预处理成 baseline JPEG（4:4:4、质量 ≥70），PDF 内不再出现 /FlateDecode 图像对象；独立于压缩档位，勾上即生效
单页图像像素上限默认 4 MP（≈12 MB 解码内存），超出等比缩小，控制翻页内存峰值

代价截图转 JPEG 体积会涨，但配合缩小页面后反而仍很小（42 KB → 66 KB，比全分辨率 JPEG 284 KB 小 4 倍），渲染快约 4.8 倍。

只要「随便看看」：为什么图片网站流畅，PDF 却卡

图片网站不给你 10 MB 原图。它按屏幕尺寸生成 1200 px 展示副本（WebP / AVIF，约 200–300 KB），滚动时按需加载、渐进渲染。PDF 没有服务端，所有页数据一次性打包在文件里，所以必须在生成时就把每张图降维到展示尺寸。

实测一张 4000×3000 / 10.3 MB 的下载原图：网站展示副本 1200×900 WebP q75 仅 236 KB（原图的 2.3%）。

做法PDF 体积解码内存单页渲染
无损嵌入原图10,346 KB34.3 MB763 ms
屏幕 150（默认档）5,358 KB34.3 MB1305 ms
极限 964,219 KB34.3 MB1364 ms
移动端一键优化294 KB4.2 MB27 ms
随便看看 · 最小最快58 KB1.4 MB6.6 ms
关键：只调 ppi / JPEG 质量几乎没用，甚至更慢。网站下载图常缺 DPI 元数据，页面被算成 41.7 英寸，触发不了下采样，4000×3000 像素原封不动。必须同时限制页面物理尺寸（最长边）和单页像素上限。

运行说明

  • 双击 ImageToPDF_Studio.exe 即可，无需安装 Python 或任何运行库；首次启动约需数秒（单文件自解压）。
  • 若被 SmartScreen 拦截：右键 → 属性 → 勾选「解除锁定」，或点「更多信息 → 仍要运行」。
  • 转换在后台线程执行，可随时「取消」；单张图片失败不会中断整批，结果弹窗会列出失败项。
  • 技术栈：PySide6（界面）+ Pillow（重采样/编码）+ PyMuPDF（PDF 封装）+ py7zr / pyzipper（压缩包），PyInstaller onefile 打包。
